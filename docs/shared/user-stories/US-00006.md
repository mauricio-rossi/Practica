# US-00006: GitHub Kanban Board Setup

**Persona:** Developer  

---

## 🧩 Description
As a developer, I want to create a GitHub Kanban Project to track both story and non-story work, so that progress can be visualized and managed efficiently across sprints.

---

## 💡 Context

This story **emerged organically** during Sprint 0 when project documentation and branching workflows were established.  
A need was identified to **create a central, visual way to track progress** for both user stories and non-story work through GitHub Issues and a Kanban Project board.

The workflow also required lightweight GitHub Project automation so issues could move through the board when linked branches and pull requests are created, reviewed, merged, or closed using GitHub issue and PR keywords.

---

## ✅ Acceptance Criteria

- A **GitHub Project (Kanban)** board is created for tracking user stories and non-story tasks.  
- Columns include: *Backlog*, *In Progress*, *In Review*, and *Done*.  
- Each story (US-00001 – US-00006) is represented as a GitHub **Issue**, linked to its branch and PR.  
- Issue naming convention:  
  `US-XXXXX: <short description>`  
- GitHub Project automation rules are configured to support issue movement through the board using linked branches, pull requests, and PR keywords such as `Closes #<issue-number>`.  
- Documentation in `docs/shared/agile-methodology.md` explains how issues, board usage, and automation rules work.  
- A sample issue is created to verify workflow linkage and automation behavior.
